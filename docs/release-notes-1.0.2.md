# 1.0.2

修复使用 PotPlayer 等播放器观看时播放中途反复出现「缓冲: XX%」问题中属于中转一侧的放大因素，并为现场取证增加诊断计数。

只读观测确认：中转在健康时段按实时速率转发（约 103 tag/s，媒体时间与墙钟比约 1.0），没有丢帧或持续欠实时；出现「缓冲」的时间段对应上游网络短时降速。上游恢复并跳到直播边缘时，会在同一条 HTTP 响应内产生多秒（本次 114.5 秒）的音视频时间戳跳变；旧版中转原样转发，播放器会把它当作流重启并重建分离器缓存，造成第二次缓冲。

本版把这类同一响应内的大时间戳跳变重基为连续时钟（音视频共用修正，跳变后从已转发时钟 +20 ms 续接；被上游跳过的内容仍然缺失，但播放器时钟不断裂）。同时：播放器写超时 5 秒 → 15 秒（对齐旧版启动器的发送超时，播放器短暂暂停读取不再导致断连重建）；上游正常媒体分段结束后的重连等待 1 秒 → 150 毫秒；`/__livehub/status` 与中转日志增加时间戳跳变计数，便于复现定位。

验证：`cargo check --locked --offline` 通过；`flv` 模块单测 14/14（含 2 个新增时间戳重基测试）；中转、重连、日志与播放器计划契约测试 31 passed / 0 failed / 4 ignored，EXIT=0；健康时段两只独立读取合计 440 秒无 >1 秒到达空档，播放器读缓存模型（2 秒）与 15 秒模型各 480 秒均为 0 次欠载。上游带宽型降速本身无法由程序消除，只缩短可恢复窗口。

下载 lite ZIP 后需自行安装并选择 mpv 或 PotPlayer；程序未签名；真实平台与硬件组合的验收范围见 validation.md。
