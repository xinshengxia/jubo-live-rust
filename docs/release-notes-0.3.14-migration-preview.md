# 0.3.14 本地迁移预览（虎牙短号房间的开播状态读取修复）

更新：2026-11-01。基线 0.3.13；数据与旧版兼容。

## 修复（用户实测反馈）

### 虎牙收藏里「安德罗妮」等短号房间读不到开播状态

- 现象：虎牙收藏卡上「安德罗妮」（短号 `a16789`）的直播状态显示为「状态待确认」，而原版 C# 能显示「直播中/重播中」。
- 根因：`mp.huya.com/cache.php?do=profileRoom` 按**短号**查询时返回 `status=422「该主播不存在」`；旧实现随后只检查房间页的 `liveStatus-on/replay/off` 标记，而虎牙房间页会把「重播中」也标成 `liveStatus-on`（2026-10-16 原版实测记录），因此无法判定，只能保持 Unknown。原版 C# 的实现里还有一步：从房间页 HTML 提取数字房号（`"profileRoom":528300`）后再查一次接口 —— Rust 移植时漏了这一步。
- 修复：`src/room_state.rs` 的虎牙分支增加数字房号回退：短号接口查不到时，先从房间页取 `"profileRoom":<数字>` 再请求一次四态接口；取不到数字号或接口仍失败时，保持原有「不猜」原则（页面 `liveStatus-on` 不冒充在播），不会把重播/下播误报成直播。
- 验证：
  - 新增纯逻辑单测（页面数字房号解析：带引号/不带引号/缺失/非法值）；
  - 真实接口人工验证（`#[ignore]` 测试）：`a16789` → 页面数字房号 528300 → `liveStatus=ON` → 解析为「直播中」；
  - 其余状态语义不变（Live/Offline/Replay/Unknown 四态，未知永远不冒充下播）。
